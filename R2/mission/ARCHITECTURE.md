# 약지기 아키텍처 — 전체 동작 설명서 (내부 학습용)

발표 용어와 실제 코드 용어를 나란히 적었습니다. 왼쪽 말로 설명하다가, 깊은 질문이 오면 오른쪽 말로 내려가면 됩니다.

---

## 1. 큰 그림 — 다섯 개의 부품

```
[사용자 화면]           [공식 검증 도구 · 대회 Runner]
 MainActivity.kt              (대회 제공 앱)
      │                            │
      ▼                            ▼
[통역사]                    [검증 통로 어댑터]
 MedDomain.kt               ChebiProbeAdapter.kt
 버튼 → 표준 사건 변환       대회 규격 → 같은 사건 형식
      │                            │
      └────────────┬───────────────┘
                   ▼
            [두뇌 · 판단 코어]
             ChebiCore.kt
             execute(사건) 함수 하나가 모든 판단
                   │
                   ▼
            [저장소]
             AndroidStateStore
             폰 안의 JSON 장부 파일 (읽기/쓰기)
```

- **화면과 검증 도구는 입구만 다르고, 같은 `ChebiCore.execute()`를 부릅니다.** 화면 전용 판단 코드가 없습니다.
- JSON은 실행되는 것이 아니라 **두뇌가 읽고 쓰는 데이터**입니다: 문제지(PROBE_INPUT), 장부(상태 저장본), 답안지(PROBE_RESULT·evidence), 설명서(MISSION_ADAPTER).

### 사건(이벤트)이란

모든 입력은 같은 모양의 "사건" 하나로 통일됩니다:

| 필드 | 뜻 | 예 |
|---|---|---|
| operation | 사건 종류 (13가지) | UPSERT_FACT(배우기), REQUEST_DECISION(판단 요청), ADVANCE_TIME(시간 경과)… |
| roles | 내용물 (이름=값 묶음) | 대상 약, 처방 값, 지시 버전, 기한… |
| virtual_time | 가상 시각 | 2026-08-01T08:00 |
| event_id | 사건 고유 번호 | EV-UI-0007 |

두뇌는 폰의 실제 시계를 보지 않고 **사건에 실린 가상 시각만** 봅니다. 그래서 "3일 뒤"를 시연에서 바로 재현할 수 있습니다.

## 2. 두 장부의 실제 구조

### 기억 장부 (memories) — 발표의 "유통기한 붙인 장부"

기억 한 건은 이렇게 생겼습니다:

```json
"mem-med_bp-STABLE_PRESCRIPTION": {
  "type": "FACT",                 ← 이름표 1: 사실 / INFERENCE(짐작) / EPHEMERAL(한시적)
  "lifetime": "STABLE",           ← 이름표 2: 계속(STABLE) / 이번만(ONE_OFF) / 기한부(TERM)
  "value": "bp_morning_1tab",     ← 내용
  "authority": "bp_v1",           ← 믿어도 되는 조건 1: 어느 지시 버전에서 나왔나
  "valid_until": "…",             ← 믿어도 되는 조건 2: 유통기한 (기한부만)
  "scope": "scope_bp",            ← 믿어도 되는 조건 3: 끊으면 같이 꺼지는 묶음
  "origin_event": "EV-…",         ← 출처: 어느 사건에서 생겼나
  "derived_from": "mem-…",        ← 출처 2: 어느 기억에서 파생됐나 (짐작 기억만)
  "status": "ACTIVE"              ← 상태: 살아있음 / INVALIDATED(무효) / CONSUMED(소모)
}
```

- **지시 버전(authority)은 약마다 따로** 관리합니다 (`authorities: { med_bp: "bp_v1", med_abx: "abx_v1" }`). 항생제 정정이 혈압약을 못 건드리는 이유.
- **잔량·도착 기록은 authority를 비워 둡니다**("권위 중립"). 지시가 아니라 "일어난 사실"이라서, 처방을 정정해도 잔량 이력은 살아남습니다.
- **삭제하면** 내용은 파일에서 제거되고 `tombstones` 목록에 이름만 남습니다. 이 흔적의 용도는 복구가 아니라 **부활 차단**입니다.

### 행동 장부 (actions) + 도착 대기 큐 (pending_outcomes)

결과가 따르는 일(리필 신청 등)은 행동으로 적힙니다:

```json
"EV-UI-0012": {
  "action_id": "action-…",
  "commit_state": "PROPOSED",     ← "하겠다" 단계. 결과 도착 후 "COMMITTED"(됐다), 취소되면 "CANCELLED"
  "outcome_id": "outcome-…"
}
```

동시에 도착 대기 큐에 `{ 결과 번호, 요청 시각, 대상 약 }`이 등록됩니다. 이후 시간 경과 사건이 올 때마다 큐를 확인해서, 요청 시각이 과거가 된 항목을 "도착" 처리합니다 — 도착하면 기억 장부에 도착 기억이 새로 적히고, 행동은 "됐다"로 바뀝니다.

## 3. 안전장치 — 세 번의 검문이 정확히 무엇을 거르나

### 검문 ① 쓸 때 (재사용 게이트) — 목록에 올릴 기억 고르기

세션을 시작하면 기억 장부 전체를 훑으며, 기억마다 다음을 순서대로 검사합니다. **하나라도 걸리면 목록에서 빠집니다.**

| 검사 | 통과 조건 | 걸러지는 실제 사례 |
|---|---|---|
| 지시 버전 | 기억의 authority = 그 약의 현재 최신 버전 (비어 있으면 무조건 통과) | 처방 정정 v1→v2 후, v1에 근거한 옛 처방 기억 |
| 유통기한 | valid_until 없음, 또는 현재 가상 시각보다 미래 | 7일 지난 항생제 |
| 묶음 | scope가 철회 목록(revoked_scopes)에 없음 | 복용 중단한 약의 전 기억, 권한 끈 알림 기억 |
| 상태 | status = ACTIVE | 한 번 쓰고 소모된 일회성, 무효 처리된 기억 |

그리고 **선택 단계의 추가 조건 둘**:
- 지금 판단하는 **그 약의 기억**만 고른다 (남의 약 기억은 유효해도 안 씀)
- 관리 밖 대상(배우자 약 = distractor)이 판단 대상이면 → 아예 **보류(ABSTAIN)** 하고 멈춘다

이 검문을 통과한 목록이 화면의 체크리스트이자, 검증 결과의 "선택된 기억" 목록입니다. **화면과 검증이 같은 함수로 이 판정을 합니다.**

### 검문 ② 바뀔 때 (충돌 게이트) — 무효로 만들 기억 고르기

| 변화 사건 | 무효가 되는 것 | 살아남는 것 |
|---|---|---|
| 처방 정정 (v1→v2) | 그 약의 v1 근거 기억 + 거기서 파생된 짐작 | 다른 약 전부, 권위 중립 기억(잔량·도착) |
| 복용 중단 (scope 철회) | 그 묶음에 속한 기억 + 파생 + **아직 안 온 그 약의 도착 대기(취소)** | 다른 묶음, 다른 약 |
| 알림 권한 회수 | 알림 묶음의 기억(예약·파생 짐작)만 | 나머지 전부 |
| 삭제 | 그 대상의 기억(원문 제거, 흔적만) + 대기 취소 | 다른 대상 전부 |

핵심 원칙: **전체 초기화가 아니라, 어긋난 것만 콕 집어서.** 무효 처리는 기록으로 남습니다(무효 목록·취소 원장).

### 검문 ③ 고칠 때 (복구 게이트) — 딸린 것 정리, 나머지 보존

- 무효가 된 기억을 **출처 연결선(derived_from)으로 역추적**해서, 거기서 파생된 짐작까지 연쇄적으로 정리합니다 (끝까지 따라감).
- 그 약의 **아직 도착하지 않은 결과 대기를 취소**하고, 걸려 있던 행동은 "취소"로 종결합니다 — 중단한 약의 리필이 나중에 도착해서 잔량을 오염시키지 않게.
- 나머지는 건드리지 않고, **보존 목록으로 명시**해서 결과에 남깁니다.

### 안전장치를 끄면 (claim-off, 비교 실험의 대조군)

스위치(`gateEnabled=false`) 하나로 세 검문이 꺼집니다. 그러면:
- 쓸 때: 검사 없이 **살아있는 기억을 통째로** 목록에 올림 → 끝난 항생제 유령 재등장
- 바뀔 때: 정밀 특정 대신 **그 대상 전체 무효화**(과잉 복구) → 정확도 0.4, 목록 1건만 생존
- 그래도 앱은 끝까지 완주 — 차이는 검문 유무뿐이라, 비교 결과는 전부 안전장치의 효과

## 4. E1 ~ E4 — 단계별로 실제 일어나는 일

### E1 Learn (배우기) — 기억 만들기

"혈압약 처방 등록" 버튼 하나가 장부에 만드는 것:

| 기억 | 이름표 | 붙는 조건 |
|---|---|---|
| 처방 내용 (bp_morning_1tab) | 사실 / 계속 | 지시 버전 bp_v1, 묶음 scope_bp |
| 잔량 6 | 사실 / 계속 | 권위 중립(지시와 무관), 묶음 scope_bp |
| 임계 5 | 사실 / 계속 | 권위 중립, 묶음 scope_bp |
| + 지시 버전 등록 | — | authorities[혈압약] = bp_v1 |

"항생제 등록"은 같은 구조에 **기한부(TERM) + valid_until(7일 뒤)**이 붙습니다.
복용 확인이 반복되면 "잘 지켜지는 시간대" 같은 **짐작(INFERENCE)** 기억이 만들어지는데, 반드시 근거 사실에 derived_from으로 연결됩니다 — 짐작이 짐작을 근거로 삼는 건 금지.

**이 분류가 원인이 됩니다**: 계속/이번만/기한부/짐작이라는 이름표와 조건이, 이후 모든 재사용·무효화·복구의 범위를 결정합니다.

### E2 Reuse (다시 쓰기) — 기억으로 오늘을 채우기

1. **세션 시작** → 도착 대기 중이던 리필이 있으면 먼저 잔량에 반영 → 검문 ① → 통과분만 체크리스트 프리필
2. **최종확인 체크** → 이것 자체가 별도 사건으로 장부에 기록 (안전확인은 자동화로 생략되지 않는다는 증거)
3. **복용 기록** → 그 슬롯(아침/저녁)에 등재된 약만 잔량 1 감산 (새 잔량 기억으로 기록)
4. **잔량 < 임계** → 리필 신청서(draft) 자동 생성 = 행동 "하겠다" + 도착 대기 등록
5. **승인** → 승인된 리필만 도착 대기에 오름 (승인 없이는 영원히 안 옴)
6. **가상 시간 경과** → 요청 시각이 지난 대기를 도착 처리 → 도착 기억 생성, 행동 "됐다"
7. **다음 세션** → 검문 ①이 도착 기억까지 통과시켜 잔량 4+30=34 반영

**앞 세션이 뒷 세션을 바꾸는 세 지점**: 목록 내용(만료·중단 제외), 가능한 행동(미등재 약은 기록 버튼 잠김), 도착 반영(승인분만).

### E3 Exception (상황 변화) — 판단의 분기

변화가 오면 두뇌는 다음 중 하나로 답합니다. 전부 결과에 그대로 적힙니다:

| 상황 | 판단 | 뜻 |
|---|---|---|
| 유효 기억이 있음 | ACT | 진행 |
| 유효 기억이 없음 | ASK | 모르니 묻겠다 |
| 오프라인인데 전송이 필요한 결정 | WAIT | 솔직하게 대기 (로컬 확인·기록은 계속) |
| 관리 밖 대상(배우자 약) | ABSTAIN | 판단 보류 |
| 미완 행동·대기 결과가 있는 관찰 | PENDING | 진행 중임을 정직하게 |
| 같은 요청이 겹쳐 옴 | 장부 상태 그대로 echo | 진행 중/완료/취소 — 새 일을 만들지 않음 |
| 옛 사건이 뒤늦게 도착 | 기각 + 사유 기록 | 지운 것 부활 금지, 구버전 지시 기각 |

### E4 Recover (되돌리기) — 부분 복구

예: "항생제 복용 중단" 버튼 하나에 일어나는 일 —

- 무효: 항생제 묶음의 처방·잔량·임계 기억, 거기서 파생된 짐작, **아직 안 온 항생제 리필 대기(취소)**, 걸려 있던 행동(취소로 종결)
- 보존: 혈압약의 모든 기억, 도착 이력, 다른 묶음 전부 — **보존 목록으로 명시 기록**
- 이후: 다음 세션 체크리스트에서 항생제는 "목록 제외"로 표시되고, 복용 기록 버튼 대상에서 빠짐

전체 초기화(Reset)와 다릅니다 — Reset은 사용자가 명시적으로 누르는 별도 버튼이고, E4는 **영향받은 성분만** 고칩니다.

## 5. 무결성 장치 — 속일 수 없게 만드는 것들

| 장치 | 동작 | 막는 것 |
|---|---|---|
| 지문 사슬 | 매 사건 후 장부 전체를 정규화 직렬화 → SHA-256. 앞 사건의 "후" 지문 = 뒷 사건의 "전" 지문 | 중간 기록 바꿔치기 (사슬이 끊겨 즉시 드러남) |
| 행동 2단계 | 하겠다(PROPOSED) → 결과 도착 후 됐다(COMMITTED) | 강제 종료를 틈탄 완료 위장 |
| 겹침 방어 | 사건 번호로 행동을 찾아 그대로 echo | 같은 복용 기록 이중 기재 |
| 삭제 흔적 | 원문 없는 이름만 남김 + 뒤늦은 옛 사건 기각 | 지운 민감 정보의 부활 |
| 가상 시계 | 판단은 사건에 실린 시각만 사용 | 기기 시계 조작, 재현 불가능성 |
| 결정론 | 모델·서버·난수 없음 | 같은 입력 = 같은 지문. 어느 폰에서든 재현·검증 가능 |

이 장치들 덕분에 "화면 조작 13단계 vs 공식 도구 13단계"에서 **강제 종료 전 8단계의 지문이 바이트까지 동일**하다는 실측이 나올 수 있었습니다 (차이는 재시작 횟수 하나 — 공식 도구만 실제로 앱을 껐다 켬).

## 6. 한 사이클 통짜 추적 — 장부에 무슨 일이 일어나나

| 사용자 행동 | 장부의 변화 |
|---|---|
| 혈압약 등록 | 기억 3건 생성(처방·잔량6·임계5) + 지시 버전 bp_v1 등록 |
| 세션 시작 | 검문① → 선택 목록 반환 → 화면 프리필 |
| 최종확인 체크 | 확인 사건 1건 기록 |
| 복용 기록 | 잔량 5 기억 기록 (6은 대체됨) |
| 한 번 더 기록 | 잔량 4 — 임계 5 미만 → 행동 "하겠다" + 도착 대기 등록 |
| 리필 승인 | 승인된 리필 대기 등록 (도착 자격 부여) |
| 3일 전진 | 대기 도착 처리 → 도착 기억 생성, 행동 "됐다" |
| 세션 시작 | 검문①이 도착 반영 → 잔량 34 |
| 처방 정정 v2 | 검문② → v1 근거 기억·파생만 무효, 잔량·도착은 보존 |

## 8. 더 깊은 층 — 위 설명이 생략한 세부

### 8-1. 두뇌가 처리하는 13가지 사건 전체

| 사건 | 하는 일 |
|---|---|
| RESET_AND_START | 새 원장에서 시작 |
| UPSERT_FACT | 배우기 — 기억 기록·갱신 |
| ADVANCE_SESSION | 세션 경계 넘기기 (기억은 유지, 관리 밖 대상 등록) |
| REQUEST_DECISION | 판단 요청 — 검문 ① 실행, 행동·대기 생성 |
| CORRECT_FACT | 정정 — 검문 ② (새 지시·새 값·새 기한) |
| REVOKE_SCOPE | 묶음 철회 — 중단·권한 회수 |
| DELETE_FACT | 삭제 — 원문 제거, 흔적만 |
| SET_NETWORK | 인터넷 켬/끔 상태 전환 |
| PROCESS_KILL_RELAUNCH | 강제 종료 후 재시작 지점 관찰 (재시작 횟수 +1) |
| REPLAY_EVENT | 같은 사건 재전달 — 겹침 방어 echo, 보류 결정 재시도 |
| DELIVER_OUT_OF_ORDER | 옛 사건의 뒤늦은 도착 — 기각 심사 |
| ADVANCE_TIME | 가상 시간 경과 — 도착 처리, 기한 만료 관찰 |
| EXPORT_AND_END | 마무리 — 미완 여부를 정직하게 보고 |

### 8-2. 짝비교 실험실의 내부 절차

1. 실험 전용으로 **서로 분리된 저장소 두 개**를 만들고, 각각 새 원장으로 초기화합니다 — 평소 쓰는 원장과도 분리라서 실험이 본 데이터를 오염시키지 않습니다.
2. 한쪽은 안전장치 켠 두뇌, 한쪽은 끈 두뇌로, **같은 8개 사건**(두 약 학습 → 첫 세션 → 3일 경과로 기한 만료 → 만료 후 판단 → 처방 정정 → 정정 후 세션)을 같은 가상 시각·같은 순서로 넣습니다.
3. **정답을 미리 적어 둡니다** — "이 정정의 실제 영향은 정확히 이 기억들"이라는 목록. 두 쪽의 실제 무효 목록을 이 정답과 대조해 정확도를 계산합니다.
4. 결과 표(유령 재사용 횟수, 정확도, 생존 목록 수, 완주 여부)를 화면에 보여주고 증거 파일로도 내보냅니다.

### 8-3. 증거 내보내기가 만드는 파일들

"증거 내보내기" 버튼은 그 순간의 장부를 여러 파일로 펼칩니다: 기억 전체(facts), 약별 지시 버전(authority), 최근 판단의 선택 목록(context_selection), 행동·도착 원장(outcomes), 흔적 목록, 비교 실험 기록(comparison), 화면 지표(ui/metrics). **화면에 보이는 것과 이 파일들은 같은 상태의 두 표현**이라, 임의 시점에 대조 검증이 가능합니다.

### 8-4. 보류 결정의 재전달 (WAIT → 재시도)

오프라인에서 전송 성격 결정이 WAIT로 보류되면, 그 사건의 번호와 원래 내용이 **보류 목록**에 저장됩니다. 연결이 돌아온 뒤 재전달 사건이 오면, 저장해 둔 **원본 사건 번호로 딱 한 번** 다시 판단합니다 — 행동이 원본 번호로 만들어지므로 사건당 최대 한 개, 즉 재시도가 겹쳐도 이중 실행이 없습니다.

### 8-5. 장부 밖에 있는 것

가상 시계의 현재값, 사건 순번, 세션 지표 같은 **화면 운영용 메타데이터**는 장부(지문 대상) 밖의 별도 설정 저장소에 둡니다. 이유: 이런 값은 기기·재실행마다 달라질 수 있어서, 지문에 넣으면 "같은 입력 = 같은 지문"이라는 결정론이 깨지기 때문입니다. 판단에 쓰이는 시각은 항상 **사건에 실려 들어온 가상 시각**입니다.

### 8-6. 자체 제작 비공개 시나리오 네 종 (발표 9장의 "네 종")

공식 공개 시험(13단계) 외에, 제가 직접 만든 시험 문제 네 벌입니다. 목적은 두 가지 —
① **처음 보는 낱말로도 동작하는가**: 네 벌 모두 앱이 한 번도 본 적 없는 단어로 사건을 적었습니다. 공개 입력의 표현에 맞춘 정답 분기가 아니라는 것을 스스로 증명하기 위해서입니다.
② **공개 시험에 없는 어려운 조합**: 오래 쓰거나 상황이 겹쳐야 드러나는 경로들.

| 벌 | 단계 | 노린 것 | 대표 확인 항목 |
|---|---|---|---|
| A | 10 | 약별 지시 분리 · 기한형 | 혈압약 정정이 항생제를 안 건드림, 정정 후 새 지시 사용, 강제 종료 후 지속 |
| B | 11 | 오프라인 · 재전달 · 삭제 | 오프라인 결정은 대기, 연결 후 원본 사건 번호로 딱 1회 재시도, 옛 지시 기각, 삭제 후 부활 없음 |
| C | 19 | 완전히 새 낱말 · 만료 경계 | 기한 안/기한 뒤 판단 차이, 오프라인 중 강제 종료, 권한 재허용 후 새 학습 사용, 삭제된 약 부활 거절 |
| D | 17 | 반복 사용의 긴 경로 | 두 번째 리필이 별개 도착으로 반영, 기한만 바뀌는 정정의 실효, 취소된 결정의 재전달은 보류로 답함, 삭제된 약의 리필은 영영 안 옴 |

네 벌 모두 공식 검증 도구로 실제 기기에서 실행해 전 항목 통과를 확인했고, D는 자체 점검에서 찾은 실패를 고친 뒤 그 수정만 정조준해 만든 재발 방지용 시험이기도 합니다.

## 부록 — 30초 요약 (통째로 외울 것)

> 모든 입력은 사건 하나로 통일되어 두뇌 하나를 지나갑니다. 두뇌는 기억 장부와 행동 장부를 들고, 기억마다 붙은 네 가지 조건 — 지시 버전, 유통기한, 묶음, 상태 — 을 세 지점에서 검문합니다. 쓸 때는 통과분만 고르고, 바뀔 때는 어긋난 것만 무효로 하고, 고칠 때는 딸린 것까지만 정리합니다. 모든 단계는 지문 사슬로 연결되어 바꿔치기가 불가능하고, 같은 입력이면 어디서든 같은 결과가 나옵니다. 이 검문 전체가 안전장치이고, 스위치 하나로 꺼서 효과를 실험으로 증명했습니다.
