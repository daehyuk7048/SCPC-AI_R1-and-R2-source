SCPC 2026 예선 2차 — Mission 선언

참가자(데이콘 닉네임): SDH · Mission 이름: 약지기 - 진화형 복약 관리

대상 사용자

만성 처방(혈압약 상시)과 단기 처방(이번 주만 항생제)을 함께 복용하는 합성 노인 페르소나 "대혁"(71세, 1인 가구) — 실존 인물·실제 환자 데이터와 무관한 완전 합성 설정이며 실제 사용자 모집·관찰은 없다. 매일 아침·저녁 복용 세션마다 오늘 먹을 약 목록·수량을 확인하고 잔량을 함께 관리한다. 반복되는 결과는 하나다: 매 세션 "확인된 복용 체크리스트"(유효성 판정을 통과한 처방, 잔량 반영)가 생성·확정되는 것이며, 성공상태와 근거는 화면과 원장에서 관찰된다. 처방·조제·배송 사건과 복용 기록·메모·잔량 등 건강 데이터 일체는 앱 내부의 합성 이벤트·합성 데이터와 가상시간으로 재현하고, 권한 상태(허용·거부·회수·재허용)는 판단 분기의 실제 입력으로 취급된다. 실제 의료기관·약국·계정·결제는 사용하지 않으며 모든 산출물은 draft/preview로만 존재한다. 이 앱은 의료 조언·진단·복약 지시가 아니고 용량·복용 여부를 스스로 정하지 않는다 — 판정 기준은 기록된 의사 지시의 최신 버전·기한·중단 scope라는 사실이며, 앱은 이를 기억·대조해 표시할 뿐이고 복용은 항상 사용자의 최종확인으로만 확정된다.

핵심 문제 (반복·중단·변화)

복약 도구는 세 방향으로 실패한다. [반복] 매 세션 처음부터 다시 물어 확인 부담이 줄지 않거나, 지난 체크리스트를 통째로 재사용해 만료된 단기약·중단된 약이 유령처럼 재등장하고 정정 전 지시 내용이 계속 표시된다. [중단] 복용 확인 도중 프로세스가 종료되면 기록·보류 질문이 사라지거나, 중복·역순 이벤트로 같은 복용 기록이 이중 기재된다. [변화] 처방 정정·복용 중단·권한 회수가 온 날에도 과거 방식을 밀어붙인다. 본질은 "어떤 기억이 지금도 유효한지 판별하고, 무효가 된 부분만 고치는 것"이다.

장기 목표 (여러 session 뒤 확인)

episode가 반복될수록 ① 직전 같은 유형 대비 불필요한 입력·재확인 단계가 감소하되 복용 전 최종확인·권한·삭제 확인은 유지되고, ② 잘못된 재사용(만료 단기약 재등장, 정정 전 지시 재표시, 삭제 원문 부활)이 게이트에 차단되어 claim-off 대비 관찰 가능하게 감소하며(목표치 0건, 발생 시 원장에 감지·기록 후 최소 범위 복구), ③ 처방·상황·권한 변화 시 질문·대기·보류·재계획·중단을 근거와 함께 선택하고, ④ 정정·중단 시 영향받은 기억 성분(그 약의 알림 예약·리필 대기·파생 추론)만 되돌리며, ⑤ 리필 draft의 지연 도착(가상시간)이 이후 세션의 잔량 판단에 실제 반영되고, ⑥ 강제 종료·중복·역순 이벤트에도 원장의 commit 경계 기준으로 복용 기록 이중 기재·삭제 부활을 감지·해소하도록 reconcile되는(목표치·복구 원칙은 ②와 동일) — 세션과 프로세스 재실행을 넘어 이어지는 진화하는 복용 체크리스트를 유지한다.

Primary value

"안전한 재사용(trustworthy reuse)" 한 가지: 지금도 유효한 처방 기억만 재사용해 확인 부담을 줄이되, 무효 기억의 재사용을 차단한다. 확인 감소와 안전은 이 한 가치의 두 측면이며, 하나의 유효조건 원장(동일한 유효성 판정) 위에서 달성하고 claim-off 대비 관찰 가능한 지표와 evidence로 보인다.

E1–E4 인과관계

[E1 Learn] 첫 세션에서 목표·필요정보·허용범위를 파악하고 각 기억을 사실(FACT: 처방 내용 — 약 단위의 지시 버전이 권위) / 추론(INFERENCE: 복용 확인 시각에서 결정론적으로 파생된 "잘 지켜지는 복용 시간대") / 일회성(EPHEMERAL: 이번 주만 항생제 — 기한 내에는 세션마다 재사용되고 기한 경과 시 만료)으로 구분하고, 유효조건(약별 지시 버전·기한·중단 scope·권한 상태)과 출처를 원장에 기록한다 — 이 분류와 유효조건이 이후 모든 재사용·판단·복구 범위를 결정하는 원인이 된다.

[E2 Reuse] 다음 세션에서 유효조건을 통과한 기억만 재사용해 오늘 목록을 프리필하고 확인 입력을 줄이되(만료·중단·소모 항목은 게이트가 프리필에서 제외함) 복용 전 최종확인은 생략하지 않고 별도 이벤트로 원장에 기재된다. 복용 확인 1회당 해당 약의 잔량 정수를 감산해 잔량·시간대 추론을 갱신하고, 잔량이 기록된 임계치 아래로 내려가면 리필 draft를 생성한다. 앞 episode에서 승인된 draft는 가상시간 경과 후 준비완료 도착 이벤트로 반영되어 이번 세션의 잔량 판단과 프리필 내용을 실제로 바꾼다.

[E3 Exception] 처방 정정(해당 약의 지시 v1→v2), 특정 약 복용 중단, 민감 메모 삭제, 네트워크 단절, 중복 복용확인 전달이 저장된 방식과 충돌하면 과거 방식을 고집하지 않고, 유효조건 매칭으로 영향 항목을 특정해 질문·대기·보류·재계획·중단 중 적절한 판단을 내린다.

[E4 Recover] 정정·중단 시 출처 링크를 역추적해 영향받은 기억 성분(그 약의 알림 예약, 미도착 리필 대기의 취소, 파생 추론의 무효화)만 되돌리고 다른 약의 유효한 학습은 보존하며, 복구된 체크리스트로 다음 세션이 정상 진행된다. 앞 episode의 선택(기억 분류, 권한 상태, 삭제, 리필 draft 승인)이 뒤 episode의 프리필 내용, 가능한 행동(만료·중단 항목의 '복용 기록' 버튼 활성/비활성 등), 도착 결과 반영이라는 서로 다른 두 지점 이상을 실제로 바꾼다.

모바일이어야 하는 이유와 mobile constraint

복용은 침상·부엌·외출 등 생활 동선의 기기에서 일어나며, 모바일에서는 권한·프로세스·네트워크·시간이 모두 휘발적이다 — 상시 프로세스인 PC 대화창이 공짜로 얻는 연속성이 여기서는 설계 대상이고, PC로 옮기면 권한 분기·강제 종료 복구·오프라인 세션 판단이라는 state·decision·evidence가 사라지거나 달라진다. 주 제약 = 알림 권한의 거부·중도 회수(Android 13+ POST_NOTIFICATIONS, 실제 OS runtime permission): 전 경로는 권한 없이 동작(화면 확인 모드)하되 권한 상태가 유효조건으로 취급되어 판단 분기를 실제로 바꾸고, 해당 권한에 묶인 기억 성분(알림 파생 추론·예약)만 무효화한다. 부 제약 = process 강제 종료·재실행 후 복용 원장·보류 질문·가상시각 복구(local continuity). 체크리스트 확정·복용 기록 같은 로컬 판단은 오프라인에서도 이어지고, 전송이 필요한 리필 draft만 보류 후 회복 시 정확히 한 번 재시도한다.

Signature mechanism — VG-Ledger (Validity-Gate Ledger)

기억마다 {유형 FACT/INFERENCE/EPHEMERAL, 유효조건(약별 지시 버전·기한·중단 scope·권한 상태), 출처 링크, 삭제 tombstone}을 기록하고 재사용·충돌·복구 세 지점이 하나의 유효성 판정을 공유한다. 문제 claim: 유효성 판정 없는 재사용은 만료·정정 전·중단 기억을 되살려 확인 감소가 안전 훼손으로 바뀐다. 효과 claim: 게이트가 있으면 무효 재사용이 차단되고 영향 특정 복구가 가능하다 — 같은 APK에서 게이트 판정만 비활성화한 claim-off(직전 체크리스트 전체 프리필, 충돌 시 전체 재확인, 정정 시 전체 재작성으로 대체하는 동일 코드경로의 기본 동작; 전 episode 정상 완주)와의 짝비교로 보인다. 두 실행은 동일 시작 snapshot을 격리된 별도 상태공간 두 개에 복제해 시작하며 mechanism on/off 외 UI·model·seed·이벤트 열·quota·network 조건은 동일하다. 지표: 세션당 입력·재확인 단계 수, 잘못된 재사용 건수, 영향 특정 정확도, 복구 보존율.
