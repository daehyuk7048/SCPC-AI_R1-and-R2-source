# SCPC 2026 예선 2차 — Mission 선언

**참가자(데이콘 닉네임): SDH** · **Mission 이름: 채비(Chebi) — 유효조건 원장 기반 진화형 외출 준비 코파일럿**

## 대상 사용자

반복 외출 루틴 2개(평일 출근, 주 2회 수영 강습)를 가진 1인 직장인 **합성 페르소나 "대혁"**.
매일 아침 가방·복장·출발시간을 준비하고 소모성 준비물의 잔량을 함께 관리한다. 반복되는
결과는 하나다: **출발 전 "확정된 준비 플랜"(항목·출발시간·잔량 반영)이 생성·확정되는 것**이며,
이 성공상태와 근거는 화면과 원장에서 관찰된다. 모든 일정·날씨·배송 사건은 앱 내부의 합성
이벤트와 가상시간으로 재현한다. 단 **위치 권한은 Android OS의 실제 runtime permission을
사용**하며(거부·회수 상태가 판단 분기의 실제 입력), 실제 서비스 계정·결제·연락처는 사용하지
않고 모든 산출물은 draft/preview로만 존재한다.

## 핵심 문제 (반복·중단·변화)

준비 도구는 세 방향으로 실패한다. **[반복]** 매번 처음부터 다시 물어 입력 부담이 줄지 않거나,
지난 플랜을 통째로 재사용해 일회성 항목이 유령처럼 재등장하고 만료된 추론이 계속 적용된다.
**[중단]** 준비 도중 앱이나 프로세스가 종료되면 진행 상태·보류 질문이 사라지거나, 중복·역순
이벤트로 상태가 어긋난다. **[변화]** 지시·상황·권한이 바뀐 날에도 과거 방식을 밀어붙인다.
문제의 본질은 "기억을 얼마나 쓰느냐"가 아니라 **"어떤 기억이 지금도 유효한지 판별하고,
무효가 된 부분만 고치는 것"**이다.

## 장기 목표 (여러 session 뒤 확인)

episode가 반복될수록 ① 같은 유형의 직전 episode 대비 **불필요한** 입력·재확인 단계가 감소하되
안전확인(권한·삭제·고위험 판단)은 유지되고, ② 잘못된 재사용(일회성 재등장, 만료된 추론 적용,
삭제 원문 부활)이 게이트에 의해 차단되어 claim-off 대비 유의하게 감소하며(목표치 0건, 발생 시
원장에 감지·기록 후 최소 범위 복구), ③ 지시·상황·권한 변화 시 질문·대기·보류·재계획·중단을
근거와 함께 선택하고, ④ 정정·철회 시 영향받은 성분만 되돌리며, ⑤ 보충 주문 draft의 지연
도착(가상시간)이 이후 준비 판단에 실제 반영되고, ⑥ 강제 종료·중복 전달·순서가 뒤바뀐 이벤트
뒤에도 원장의 commit 경계 기준으로 같은 행동이 두 번 실행되거나 삭제 항목이 부활하지 않게
reconcile되는 — 세션과 프로세스 재실행을 넘어 이어지는 **진화하는 준비 플랜**을 유지한다.

## Primary value

**"안전한 재사용(trustworthy reuse)" 한 가지**: 지금도 유효한 기억만 재사용해 부담을 줄이되,
무효 기억의 재사용을 차단한다. 입력 감소와 안전은 이 한 가치의 두 측면이며, **하나의 유효조건
원장(동일한 유효성 판정)** 위에서 달성하고 claim-off 대비 관찰 가능한 지표와 evidence로 보인다.

## E1–E4 인과관계

**[E1 Learn]** 첫 준비에서 목표·필요정보·허용범위를 파악하며 각 기억을 사실(FACT) /
추론(INFERENCE) / 일회성(EPHEMERAL)으로 구분하고, 유효조건(요일·강수·만료·권한 상태 등)과
출처를 원장에 기록한다 — 이 분류와 유효조건이 이후 모든 단계의 재사용·판단·복구 범위를
결정하는 원인이 된다.

**[E2 Reuse]** 다음 유사 준비에서 유효조건을 통과한 기억만 자동 재사용해 입력을 줄이고
(일회성 항목은 재등장하지 않음), 실제 사용 기록으로 이동시간·잔량 추론을 갱신하며, 부족 시
보충 주문 draft를 생성한다. 앞 episode에서 승인된 draft는 가상시간 경과 후 **도착 이벤트로
반영되어 이번 준비의 재고 판단과 프리필 내용을 실제로 바꾼다.**

**[E3 Exception]** 사용자의 지시·목표 변경(예: "오늘은 수영 안 감"), 날씨 정정, 일정 변경,
권한 회수 같은 사건이 저장된 방식과 충돌하면 과거 방식을 고집하지 않고, 유효조건 매칭으로
영향 항목을 특정해 질문·대기·보류·재계획·중단 중 적절한 판단을 내린다.

**[E4 Recover]** 오보 정정·부분 철회 시 출처 링크를 역추적해 영향받은 성분만 되돌리고 유효한
학습은 보존하며, 복구된 플랜으로 다음 준비가 정상 진행된다. 이로써 앞 episode의 선택(기억
분류, 권한 상태, 삭제, 보충 주문 draft 승인)이 뒤 episode의 프리필 내용, 가능한 행동(버튼
활성/비활성), 도착 결과 반영이라는 **서로 다른 두 지점 이상**에서 가능한 행동을 실제로 바꾼다.

## 모바일이어야 하는 이유와 mobile constraint

아침 준비는 침실·현관·이동 중에 일어나는 모바일 고유의 사용 맥락이며, 모바일에서는 권한·
프로세스·네트워크·시간이 모두 휘발적이다 — 상시 프로세스인 PC 대화창이라면 공짜로 얻는
연속성이 여기서는 설계 대상이 된다(state·decision·evidence가 사라지거나 어긋나는 지점이
mobile counterfactual). 주 제약 = **선택 권한(위치)의 거부·중도 회수**: 전 경로는 권한 없이
동작(이동시간 수동값 대체)하되, 권한 상태가 기억의 유효조건으로 취급되어 판단 분기를 실제로
바꾼다. 부 제약 = **process 강제 종료·재실행** 후 플랜·보류 질문·가상시각을 원장에서
복구(local continuity)하며, 오프라인에서도 판단·복구·export가 동작한다.

## Signature mechanism — VG-Ledger (Validity-Gate Ledger)

모든 기억 항목에 {유형(사실/추론/일회성), 유효조건 술어, 출처 링크, tombstone}을 부여하고,
동일한 유효성 판정이 세 지점에서 작동한다: ① **재사용 게이트**(유효조건 통과분만 프리필)
② **충돌 게이트**(신규 이벤트를 유효조건과 매칭해 영향 항목만 특정) ③ **복구 게이트**(출처
역추적으로 영향 성분만 롤백). **문제 claim**: 유형·유효조건 없는 기억 재사용은 유령 항목,
만료된 추론의 적용, 과잉 재확인, 과잉 복구를 낳는다. **효과 claim**: 게이트가 켜지면 입력
부담이 줄면서도 잘못된 재사용이 차단되고, 정지·복구가 최소 범위로 정밀해진다. 같은 APK의
claim-off(**게이트 판정만 비활성화** — 유효조건 없이 직전 플랜 전체를 프리필하고, 충돌 시
전체 재확인, 정정 시 전체 재작성으로 대체; **상태공간은 full과 완전히 격리된 별도 사본**,
UI·이벤트 순서·quota·network 조건 동일) 대비 사용자 입력 단계 수, 잘못된 재사용 건수, 영향
특정 정확도, 복구 보존율로 측정한다.
