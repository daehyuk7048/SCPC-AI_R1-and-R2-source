# SCPC 2026 예선 2차 — Mission 선언 (MedKeeper 초안 V1)

**참가자(데이콘 닉네임): SDH** · **Mission 이름: 약지기 - 진화형 복약 관리**

## 대상 사용자

만성 처방(혈압약 상시)과 단기 처방(이번 주만 항생제)을 함께 복용하는 **합성 노인 페르소나
"대혁"(71세, 1인 가구)**. 매일 아침·저녁 복용 세션마다 오늘 먹을 약 목록·수량을 확인하고 잔량을
함께 관리한다. 반복되는 결과는 하나다: **매 세션 "확인된 복용 체크리스트"(지금 유효한 처방만,
잔량 반영)가 생성·확정되는 것**이며, 이 성공상태와 근거는 화면과 원장에서 관찰된다. 모든
처방·검사·배송 사건은 앱 내부의 합성 이벤트와 가상시간으로 재현하며, **권한 상태(허용·거부·회수)는
판단 분기의 실제 입력으로 취급된다.** 실제 의료기관·약국·계정·결제는 사용하지 않고 모든 산출물은
draft/preview로만 존재한다. 이 앱은 의료 조언이 아니며 용량을 스스로 정하지 않는다 — **의사 지시의
최신 버전을 기억하고 대조할 뿐이다.**

## 핵심 문제 (반복·중단·변화)

복약 도구는 세 방향으로 실패한다. **[반복]** 매 세션 처음부터 다시 물어 확인 부담이 줄지 않거나,
지난 체크리스트를 통째로 재사용해 만료된 단기약·중단된 약이 유령처럼 재등장하고 정정 전 용량이
계속 적용된다. **[중단]** 복용 확인 도중 앱·프로세스가 종료되면 기록·보류 질문이 사라지거나,
중복·역순 이벤트로 같은 복용이 두 번 기재된다. **[변화]** 처방 정정·복용 중단·권한 회수가 온
날에도 과거 방식을 밀어붙인다. 문제의 본질은 "기억을 얼마나 쓰느냐"가 아니라 **"어떤 기억이
지금도 유효한지 판별하고, 무효가 된 부분만 고치는 것"**이다.

## 장기 목표 (여러 session 뒤 확인)

episode가 반복될수록 ① 같은 유형의 직전 episode 대비 **불필요한** 입력·재확인 단계가 감소하되
복용 전 최종확인(안전확인)·권한·삭제 확인은 유지되고, ② 잘못된 재사용(만료 단기약 재등장, 정정
전 용량 적용, 삭제 원문 부활)이 게이트에 의해 차단되어 claim-off 대비 관찰 가능하게 감소하며
(목표치 0건, 발생 시 원장에 감지·기록 후 최소 범위 복구), ③ 처방·상황·권한 변화 시
질문·대기·보류·재계획·중단을 근거와 함께 선택하고, ④ 정정·중단 시 영향받은 성분만 되돌리며,
⑤ 리필 draft의 지연 도착(가상시간)이 이후 세션의 잔량 판단에 실제 반영되고, ⑥ 강제 종료·중복
전달·순서가 뒤바뀐 이벤트 뒤에도 원장의 commit 경계 기준으로 같은 복용이 두 번 기재되거나 삭제
항목이 부활하지 않게 reconcile되는 — 세션과 프로세스 재실행을 넘어 이어지는 **진화하는 복용
체크리스트**를 유지한다.

## Primary value

**"안전한 재사용(trustworthy reuse)" 한 가지**: 지금도 유효한 처방 기억만 재사용해 확인 부담을
줄이되, 무효 기억의 재사용을 차단한다. 확인 감소와 안전은 이 한 가치의 두 측면이며, **하나의
유효조건 원장(동일한 유효성 판정)** 위에서 달성하고 claim-off 대비 관찰 가능한 지표와 evidence로
보인다.

## E1–E4 인과관계

**[E1 Learn]** 첫 세션에서 목표·필요정보·허용범위를 파악하고 처방·복용시간 등 구체 기억을
학습하며, 각 기억을 사실(FACT: 처방 내용 — 지시 버전이 권위) / 추론(INFERENCE: 복용 기록에서
파생된 "잘 지켜지는 시간대") / 일회성(EPHEMERAL: 이번 주만 항생제)으로 구분하고, 유효조건(지시
버전·기한·중단 scope·권한 상태)과 출처를 원장에 기록한다 — 이 분류와 유효조건이 이후 모든 단계의
재사용·판단·복구 범위를 결정하는 원인이 된다.

**[E2 Reuse]** 다음 세션에서 유효조건을 통과한 기억만 자동 재사용해 오늘 복용 목록을 프리필하고
확인 입력을 줄이되(만료·중단·소모 항목은 재등장하지 않음) **복용 전 최종확인은 생략하지 않는다.**
복용 확인 기록으로 잔량·시간대 추론을 갱신하며, 잔량 임계치에서 리필 draft를 생성한다. 앞
episode에서 승인된 draft는 가상시간 경과 후 **준비완료 도착 이벤트로 반영되어 이번 세션의 잔량
판단과 프리필 내용을 실제로 바꾼다.**

**[E3 Exception]** 처방 정정(용량 변경, 지시 v1→v2), 특정 약 복용 중단, 민감 메모 삭제, 네트워크
단절, 중복 복용확인 전달 같은 사건이 저장된 방식과 충돌하면 과거 방식을 고집하지 않고, 유효조건
매칭으로 영향 항목을 특정해 질문·대기·보류·재계획·중단 중 적절한 판단을 내린다.

**[E4 Recover]** 정정·중단 시 출처 링크를 역추적해 영향받은 성분(그 약의 알림·리필 대기·파생
추론)만 되돌리고 다른 약의 유효한 학습은 보존하며, 복구된 체크리스트로 다음 세션이 정상 진행된다.
이로써 앞 episode의 선택(기억 분류, 권한 상태, 삭제, 리필 draft 승인)이 뒤 episode의 프리필 내용,
가능한 행동(복용 완료 버튼 활성/비활성 등), 도착 결과 반영이라는 **서로 다른 두 지점 이상**을
실제로 바꾼다.

## 모바일이어야 하는 이유와 mobile constraint

복용은 침상·부엌·외출 등 생활 동선의 기기에서 일어나고, 자택 네트워크가 불안정해도 세션 판단이
이어져야 한다(오프라인 기본 동작). **알림 권한 상태가 판단 분기의 실제 입력**이다: 거부·회수 시
알림 경로 없이 화면 확인 모드로 안전하게 대응하고, 해당 권한에 묶인 성분만 무효화한다. process
종료·재실행 뒤에도 복용 원장과 보류 질문이 복구되어 이어진다. PC 대화창과 달리 state·판단·근거가
기기 원장에 영속되어 세션·재실행을 넘어 관찰된다.

## Signature mechanism — VG-Ledger

기억마다 {유형 FACT/INFERENCE/EPHEMERAL, 유효조건(지시 버전·기한·중단 scope), 출처 링크, 삭제
tombstone}을 기록하고, **재사용(프리필 선택)·충돌(정정·중단의 영향 특정)·복구(출처 역추적)** 세
지점이 하나의 유효성 판정을 공유한다. **문제 claim**: 유효성 판정 없는 재사용은 만료·정정 전·중단
기억을 되살려 확인 부담 감소가 안전 훼손으로 바뀐다. **효과 claim**: 게이트가 있으면 무효 재사용이
차단되고 영향 특정 복구가 가능하다 — claim-off(유효조건 없이 직전 체크리스트 전체를 프리필하고,
충돌 시 전체 재확인, 정정 시 전체 재작성하는 **성실하지만 순진한 기본 동작**; 전 episode 정상
완주)와 같은 시작 snapshot·같은 이벤트 열의 짝비교로 관찰 가능하게 보인다.
