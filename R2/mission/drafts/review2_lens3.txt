## 1. [중] E2 동결문 "실제 사용 기록으로 이동시간·잔량 추론을 갱신하며" — 추론 갱신 파이프라인을 2종 약속

**문제**: V2 49행. `e1_e4_causal_chain`은 동결되는데, 잔량 갱신(보급 흐름의 핵심)과 별개로 "이동시간 추론 갱신"까지 동결 약속이 된다. 5일 구현에서 이동시간 학습이 잘려나가면 "선언과 일치"(04_SUBMISSION_GUIDE 56행) 검사에서 인과사슬 문면 미이행이 된다. quota 60step 안에서 사용 기록 이벤트를 추가 배치해야 하는 시나리오 부담도 있다.

**유지 판정 — 유지 가능, 단 최소 구현 계약을 지금 확정할 것.** "실제 사용 기록"은 합성 세계 안의 앱 내 기록이므로, **합성 사용 이벤트 1건(예: 실제 출발이 5분 지연) → 이동시간 INFERENCE 값 1회 결정론적 갱신**이면 문면이 충족된다(UPSERT/CORRECT 1스텝, ML 불요). 이 갱신은 E1의 INFERENCE 분류 예시를 하나 더 주고 위치 권한 축과도 연결되므로 오히려 자산이다. 축소가 불가피해 보이면 지금(동결 전) 대체: "실제 사용 기록으로 잔량 등 추론을 갱신하며" — 단, 이 경우 이동시간—권한—출발시간 축의 응집이 약해지므로 권장하지 않음.

## 2. [중] target_user 동결문 "위치 권한은 Android OS의 실제 runtime permission을 사용" — 권한을 요청만 하고 실사용처가 없으면 CODE/SEC·심사 공격 지점

**문제**: V2 11–12행. CODE/SEC 단계는 permission을 검사하고(05_EVALUATION 파이프라인), granted 상태에서 위치를 어디에도 쓰지 않으면 "미사용 권한 요청" 트집이 가능하다. 오프라인 기본 모드라 지도 API 사용도 불가하므로 실사용처가 자명하지 않다.

**유지 판정 — 문구는 유지(G7 방어에 필수), 구현 계약으로 해소.** 선언 문면은 "거부·회수 **상태**가 판단 분기의 실제 입력"이라고만 약속하므로 과잉 약속은 아니다. 다만 granted 상태에 최소 1개 실사용처를 구현할 것: **권한 granted ↔ '이동시간 자동 추정' 기능(버튼) 활성, denied/회수 ↔ 비활성+수동값** — 이것이 E4 동결문의 "버튼 활성/비활성" 지점과 정확히 겹쳐 1구현 2방어가 된다. 문구 수정 불요.

## 3. [중하] long_horizon_goal ② "claim-off 대비 **유의하게** 감소" — 통계적 유의성으로 읽히는 동결 어휘

**문제**: V2 28행. "유의하게"는 통계 검정을 연상시키는데, comparison은 같은 snapshot의 단일 짝실행(03_TECH §7)이라 유의성 입증이 구조적으로 불가능하다. 동결 필드이므로 심사 시 "선언한 '유의성'을 보여라"는 트집에 대응 수단이 없다.

**대체 문구**: "claim-off 대비 **관찰 가능하게** 감소하며(목표치 0건, 발생 시 원장에 감지·기록 후 최소 범위 복구)" — 한 단어 교체로 동일 강도, 반증 리스크 제거. Primary value 절(39행)은 이미 "관찰 가능한 지표"로 쓰고 있어 이 교체가 문서 내부 일관성도 맞춘다.

## 4. [하] E4 동결문 "가능한 행동(버튼 활성/비활성)" — 닫힌 괄호

**문제**: V2 59–60행. 최종 UI에서 가능행동 변화가 섹션 숨김·입력란 잠금 등으로 표현되면 문면 불일치 시비 여지. (단 2번 항목의 버튼 토글을 구현하면 실질 리스크는 낮다.)

**대체 문구**: "가능한 행동(버튼 활성/비활성 **등**)" — 비용 0의 보험.

## 5. [하] claim-off 동일 조건 목록에 seed 누락

**문제**: V2 82행 "UI·이벤트 순서·quota·network 조건 동일"은 02_DEFINE 69행의 표준 목록("UI, model, seed, event order, quota와 network")에서 model·seed가 빠져 있다. 결정론 구현이면 실질 무해하나 표준 문구 대조 트집 여지.

**대체 문구**: "UI·이벤트 순서·seed·quota·network 조건 동일" (mechanism 절은 비동결이므로 기술노트에서 보강해도 무방 — 분량 여유 있으면 지금 반영).

## CII Judge 시뮬레이션 결과 (렌즈 2) — 이상 없음, 근거:

- **C1**: 문제 claim(77–78행)은 4개 실패 양상(유령 항목·만료 추론·과잉 재확인·과잉 복구)을, 효과 claim(78–79행)은 3개 개선 방향+지표 4종을 결과 관찰 전에 특정 — C1(05_EVALUATION 184행 "claim이 분명한가") 기준 충족. 지표 4종 전부 측정 약속은 **비동결 절**에 있고 C1 claim의 공식 등록 시점은 "최종 release"(02_DEFINE 66행)이므로, 구현 중 지표 축소·교체 가능 — 동결 리스크 아님.
- **"일부러 약하게 만든 데모" 공격 방어**: "별도의 약한 demo나 다른 APK 대체 금지"(01_OVERVIEW 37–38행)는 별도 산출물 대체 금지 규정이지 off arm의 동작 수준 규정이 아니다. V2의 off 대체정책(80–82행)은 각 항목이 "유효조건 부재의 강제 귀결"로 서술됨: 유효조건이 없으면 프리필 시 걸러낼 수단이 없어 전체 재사용, 충돌 시 영향 특정이 불가해 전체 재확인, 정정 시 역추적이 불가해 전체 재작성 — 이는 core_problem(17–20행)이 기술한 기존 도구의 전형 동작 및 02_DEFINE 40행의 기피 방식과 1:1 대응하는 '성실하지만 순진한' baseline이다. 문제 claim의 예언(과잉 재확인·과잉 복구)과 off 동작이 정확히 짝을 이뤄 오히려 C3 정합성 강점. **잔여 보강(비동결, 기술노트에서)**: "claim-off arm도 전 episode를 정상 완주하는 보수적 기본 동작"임을 한 문장 명시하고, comparison 실행에서 off arm 정상 완료 evidence를 남길 것.
- **C3 짝비교 성립성**: 4개 지표 모두 off arm 값이 정의됨(전체 재확인→입력 단계 수↑, 전체 프리필→잘못된 재사용 건수↑, 전체 특정→정확도 저하, 전체 재작성→보존율 저하). "영향 특정 정확도"만 시나리오별 ground truth(실제 영향 항목 집합) 정의가 필요 — 구현 시 시나리오 스펙에 명기할 것(문서 수정 불요).
